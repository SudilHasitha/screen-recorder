Why this over OBS?

  • Privacy-first: recordings never leave your machine. No servers, no accounts.
  • Zero install: runs in your browser on Linux/Windows/macOS/Android Chrome. Great for locked-down machines.
  • One-click start: no scene/source setup — use the browser's secure picker.
  • System + Mic mix: combines tab/system audio with mic locally via Web Audio.
  • Save while recording: on Chromium, stream straight to disk — safer for long sessions.
  • Open format: WebM (VP8/VP9 + Opus) plays in modern players and browsers.

Limitations vs OBS

  • Advanced pipelines (filters/scenes/NDI/virtual cams/RTMP) are OBS territory.
  • Whole-screen system audio support varies by OS/compositor; tab audio is most reliable. Android Chrome cannot capture system audio.
  • Android Chrome may omit getDisplayMedia until screen capture is enabled (see the setup guide). iOS cannot capture the screen from a web page.
  • Outputs are WebM; MP4 requires local post-convert (e.g., ffmpeg or ffmpeg.wasm).

Troubleshooting

  • If you don't see system audio, share a tab and check "Share tab audio" (desktop). Android Chrome cannot capture system audio.

Setup guides

Record Android apps in Chrome (getDisplayMedia)
  1. Use Google Chrome (not Samsung Internet, Firefox, or an in-app browser such as Instagram / Gmail).
  2. Open this page over HTTPS. getDisplayMedia is missing on plain HTTP.
  3. Update Chrome from the Play Store, then relaunch it.
  4. If Start still says getDisplayMedia is not found, enable capture flags:
    • Open chrome://flags/#user-media-screen-capturing and set User Media Screen Capturing to Enabled.
    • Open chrome://flags/#android-media-picker and set Android Media Picker to Enabled if the flag exists.
    • Tap Relaunch.
  5. Tap Start, then in the Android prompt choose a screen or another app (not only a Chrome tab). Allow the system screen-capture permission.
  6. Keep Chrome in the background while you use the app you want recorded. Stop from the notification or return here and tap Stop.

Chrome on phones may still hide getDisplayMedia until those flags are on. Tablets / desktop-class Android often already have it. iOS cannot capture the screen from a web page.

Enable File System Access (save-to-disk while recording)

The Save dialog (showSaveFilePicker) lets Chrome write the recording straight to a file you choose. If it is off, this app falls back to browser storage or a download.

  1. Use HTTPS (or localhost). The API is blocked on insecure pages.
  2. Chrome / Edge (desktop): it is on by default. If missing, open chrome://flags/#file-system-access-api (or edge://flags/#file-system-access-api), enable it, and relaunch.
  3. Brave: open brave://flags/#file-system-access-api, enable File System Access API, and relaunch Brave.
  4. Chrome on Android (132+): File System Access is available. Update Chrome if the live-save checkbox stays disabled. If the Save dialog still does not appear, enable chrome://flags/#file-system-access-api and relaunch.
  5. Reload this page and check the feature line above for File System Access.

Firefox and Safari do not implement the Save dialog. On those browsers, record to memory and use Download (or Share on Android).
