Why this over OBS?

  • Privacy-first: recordings never leave your machine. No servers, no accounts.
  • Zero install: runs in your browser on Linux/Windows/macOS/Android Chrome. Great for locked-down machines.
  • One-click start: no scene/source setup — use the browser's secure picker.
  • System + Mic mix: combines tab/system audio with mic locally via Web Audio.
  • Save while recording: on Chromium, stream straight to disk — safer for long sessions.
  • Open format: WebM (VP8/VP9 + Opus) plays in modern players and browsers.

Limitations vs OBS

  • Advanced pipelines (filters/scenes/NDI/virtual cams/RTMP) are OBS territory.
  • Whole-screen system audio support varies by OS/compositor; tab audio is most reliable. Android Chrome cannot capture system audio.
  • Chrome on many phones still treats getDisplayMedia as experimental. Enable the two Chrome flags in Troubleshooting if Start reports it missing. iOS cannot capture the screen from a web page.
  • Outputs are WebM; MP4 requires local post-convert (e.g., ffmpeg or ffmpeg.wasm).

Troubleshooting

  • If you don't see system audio, share a tab and check "Share tab audio" (desktop). Android Chrome cannot capture system audio.

  • Chrome on Android hides getDisplayMedia unless both flags are Enabled, then relaunch: chrome://flags/#enable-experimental-web-platform-features and chrome://flags/#user-media-screen-capturing.

Enable File System Access

This site is already served over HTTPS. If live-save is disabled, turn on the Save dialog in the browser:

  1. Chrome / Edge: chrome://flags/#file-system-access-api or edge://flags/#file-system-access-api → Enabled → relaunch.
  2. Brave: brave://flags/#file-system-access-api → Enabled → relaunch.
  3. Reload this page. The feature line above should show File System Access.

Firefox and Safari have no Save dialog — use Download (or Share on Android). If the picker is still off, live save uses private browser storage instead.
